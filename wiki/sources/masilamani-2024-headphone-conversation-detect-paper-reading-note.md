## 一、问题定义：耳机透明模式的误触发

在嘈杂环境（餐厅、交通工具）中，戴 ANC 耳机与人交谈很困难。现有的透明模式（transparency mode）存在两个核心问题：

1. **误触发**：咳嗽、咀嚼、哼歌、自言自语等非对话声音会错误激活透明模式
2. **错误停用**：对话中途短暂停顿时透明模式过早关闭，导致体验断裂

**设计目标**：仅在**真正的面对面对话**（与 ~2m 内的目标说话者）时激活透明模式，对话结束后自动切回 ANC。

## 二、系统架构

### 2.1 整体 DSP 架构

```
┌──────────────────────────────────────────────────────────┐
│                    耳机 DSP 架构                          │
│                                                          │
│  外部参考麦克风 ──→                                       │
│  语音麦克风 ──────→  [Conversation Detector] ──→ 对话声明 │
│  骨传导传感器 ────→              ↓                        │
│  IMU (加速度计/陀螺仪) ──→  [Filter Block]               │
│                              ↓    ↓                      │
│                        ANC    透明模式                    │
│                         ↓      ↓                         │
│                   [扬声器输出]                             │
└──────────────────────────────────────────────────────────┘
```

### 2.2 核心组件

| 组件 | 功能 |
|------|------|
| **OVAD** (Own Voice Activity Detector) | 检测佩戴者自己的语音活动 |
| **TVAD** (Target Voice Activity Detector) | 检测远场目标说话者的语音活动 |
| **Idle Threshold Monitor** | 监控 OVAD 和 TVAD 同时不活动的持续时间 |
| **Filter Block** | 根据对话声明动态切换音频路径（ANC ↔ 透明模式） |

## 三、对话检测核心机制

### 3.1 双 VAD 架构

```
OVAD: 佩戴者说话？──→ [是/否]
                      ↓ 同时为"否"且持续 > 阈值？
TVAD: 目标说话？──→ [是/否]
                      ↓
                  对话结束声明
```

**对话开始**：OVAD 和 TVAD 中至少一个检测到语音活动。

**对话结束**：OVAD 和 TVAD **同时**不活动的持续时间超过**自适应空闲阈值**。

### 3.2 自适应空闲阈值

空闲阈值不是固定的——它会随着时间**自适应调整**：

- 跟踪历史透明模式不活动周期
- 跨天/周学习用户的对话停顿模式
- 也可以使用 ML 模型直接预测对话终止

### 3.3 处理流程

```
For each time window (>100ms, <300ms 重叠窗口):
  1. 运行 OVAD → 佩戴者语音标志
  2. 运行 TVAD → 目标语音标志
  3. 如果两者同时为"否":
     空闲计时器 += 窗口长度
  4. 如果空闲计时器 > 自适应阈值:
     声明对话结束 → 关闭透明模式 → 切回 ANC
  5. 否则:
     保持透明模式
```

## 四、误触发拒绝机制

### 4.1 三阶段标志系统

| 阶段 | 检测内容 | 目的 |
|------|---------|------|
| **阶段 1** | 自己语音检测 | 区分佩戴者声音 vs 外部声音 |
| **阶段 2** | 语言 vs 非语言分类 | 排除咳嗽、咀嚼、哼歌等 |
| **阶段 3** | 远场活动分析 | 确认是否有真正的远场说话者 |

### 4.2 ML 辅助识别

使用 ML 模型关联麦克风、骨传导和媒体播放信号，识别：
- **哼歌/唱歌**：骨传导有振动 + 麦克风有音频 + 媒体播放可能同步
- **自言自语**：OVAD 有活动但 TVAD 无活动
- **咳嗽/清嗓**：短时非语言声音

### 4.3 双耳验证

左/右耳塞实例**交换检测消息**，设置一致/不一致标志：

```
左耳: 检测到对话？──→ [是] ──┐
                              → 一致标志 → 高置信度激活
右耳: 检测到对话？──→ [是] ──┘

左耳: 检测到对话？──→ [是] ──┐
                              → 不一致标志 → 低置信度，可能误触发
右耳: 检测到对话？──→ [否] ──┘
```

## 五、说话人 ID 与对话签名

### 5.1 声纹匹配

生成目标说话者的**声纹（voice print）**，将新的语音片段与存储的声纹匹配，无需依赖头部方向即可声明对话。

### 5.2 对话签名（Conversation Signature）

基于**词间间隔模式（inter-word gap patterns）**生成对话签名。每个人的说话节奏和停顿模式是独特的——这可以作为对话的"指纹"。

**优势**：有效处理偏离轴线的说话者或重叠的背景说话者。

---

## 六、动态波束形成孔径

### 6.1 头部偏航角跟踪

使用 IMU（加速度计/陀螺仪）跟踪佩戴者的**头部偏航角（head yaw）**，动态调整麦克风拾音波束的角度和宽度。

### 6.2 孔径动态调整

| 条件 | 孔径行为 |
|------|---------|
| 佩戴者看向说话者 | 孔径收缩（<180°），聚焦目标 |
| 佩戴者转头看别处 | **立即**扩展孔径 |
| 佩戴者转回 | 使用**时间常数衰减**慢慢收缩 |

### 6.3 实现策略

- **ML 优化**：学习用户的头部运动模式，预测最佳孔径
- **预定义孔径状态**：为计算效率，限制在几个预设孔径状态之间切换

---

## 七、地理围栏（行人边界）

### 7.1 边界定义

在佩戴者位置周围定义一个**行人边界**（通过配对的伴侣设备 via Bluetooth 跟踪位置）。

### 7.2 对话终止判定

```
如果佩戴者停止说话 AND  crossing 行人边界:
    → 声明对话结束
    → 覆盖残留的 TVAD 活动（可能来自旁观者）
```

**优势**：即使 TVAD 仍在检测到语音（比如路过的陌生人），佩戴者离开对话区域即可可靠终止对话模式。

---

## 八、音频路由与处理

### 8.1 对话模式下的音频路径

对话声明后，Filter Block 从 ANC/普通透明模式切换到**对话聚焦路径**：

1. **波束形成**：聚焦目标说话者方向
2. **统计算法**：分离目标语音与背景噪声
3. **ML 分离**：直接分离目标说话者

### 8.2 平滑过渡

**缓冲 ~1 秒的预声明环境音频**——消除透明模式开启时的突兀感。

### 8.3 媒体播放处理

对话期间，正在播放的媒体音频被处理：

| 处理方式 | 效果 |
|---------|------|
| **人声去除** | 从媒体中剥离人声，保留背景音乐 |
| **音频闪避（Ducking）** | 降低背景媒体音量 |
| **空间化** | 将立体声空间化为头外单声道，避免干扰对话感知 |

## 九、与 [[fukumoto-2025-whisphone-paper-reading-note|Whisphone]] 的对比

| 维度 | [[fukumoto-2025-whisphone-paper-reading-note|Fukumoto 2025: Whisphone Paper Reading Note]] | Masilamani 2024: Headphone Conversation Detect |
|------|------|------|
| **核心目标** | 耳语私密输入 | 自动检测对话并切换透明模式 |
| **麦克风位置** | 耳道内（骨传导辐射） | 外部参考麦克风 + 语音麦克风 |
| **信号处理** | 闭塞效应 + ANC 降噪 | 双 VAD + 自适应空闲阈值 + 波束形成 |
| **应用场景** | AI 助手私密语音输入 | 嘈杂环境中面对面交谈 |
| **ANC 角色** | 用于改善耳语拾音信噪比 | 用于非对话时的降噪 |
| **传感器融合** | 仅耳道内麦克风 | 麦克风 + 骨传导 + IMU + 摄像头（可选）+ 配对设备 |

**互补关系**：Whisphone 解决了"如何私密地输入语音"，而本专利解决了"如何自动检测何时需要听到外界对话"。两者可以整合——Whisphone 的耳语拾音可以作为本专利的 OVAD 输入源之一。

## 十、技术权利要求

基于专利披露，权利要求覆盖：

1. **数字音频处理器/滤波器块**：基于双 VAD（OVAD/TVAD）监控和自适应空闲阈值，在 ANC 和对话聚焦透明模式之间动态切换
2. **误触发检测方法**：多阶段标志 + ML 关联麦克风/骨传导/媒体播放信号
3. **双耳验证机制**：左/右耳塞共享误触发检测，设置一致/不一致标志
4. **自适应孔径波束形成**：头部偏航历史控制、立即扩展、时间常数衰减
5. **行人边界穿越终止对话**：由伴侣设备管理
6. **透明模式下的动态媒体播放调整**

## 十一、Q&A

**Q1: 为什么需要自适应空闲阈值而不是固定值？**

不同用户的对话停顿模式差异很大。有人说话连贯（短停顿），有人喜欢长时间思考（长停顿）。固定阈值要么导致过早切断（阈值太短），要么导致透明模式不必要地保持开启（阈值太长）。自适应阈值通过学习用户的历史对话模式，在个人化水平上优化切换时机。

**Q2: 双耳验证如何提高置信度？**

单耳检测容易受局部噪声干扰（比如一只耳附近有人咳嗽）。双耳同时检测到对话信号时，置信度大幅提升。不一致时（一只耳检测到、另一只没有），系统可以选择保守策略（不激活）或要求更多证据。

**Q3: 行人边界机制解决了什么问题？**

在拥挤的街道上，TVAD 可能持续检测到路过的陌生人说话，导致透明模式无法正确关闭。地理围栏提供了**空间维度的对话终止条件**——佩戴者离开对话区域即声明结束，不受残留语音活动干扰。

**Q4: 这个专利与现有耳机的"语音检测"功能有什么区别？**

现有耳机（如 AirPods Pro）的语音检测主要基于佩戴者自己的语音（OVAD）。本专利的创新在于：
1. **双 VAD 架构**：同时监控佩戴者和目标说话者
2. **自适应空闲阈值**：而非固定超时
3. **多模态误触发拒绝**：骨传导 + ML 排除哼歌/咳嗽
4. **双耳交叉验证**：提高决策置信度
5. **地理围栏终止**：空间维度的对话结束判定
6. **动态波束形成孔径**：基于头部偏航角自动调整拾音范围
