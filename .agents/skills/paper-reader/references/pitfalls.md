# Common Pitfalls

Concrete lessons from prior ingests. Skim this list before starting an ingest and consult it when something unexpected happens.

1. **Brace glob on Windows fails silently** — `wiki/entities/{a,b,c}.md` returns "No file found" even when files exist. Use Grep with alternation or multiple parallel Globs (see "Checking Existing Pages" in SKILL.md).

2. **Citation discrepancies propagate** — Later papers often cite earlier work with wrong numbers (e.g., EchoFree 2025 cited Seidel 2024 with 1.62M params / 107 MMACs/s / 100 Bark bands, but the original reports 1.58M / 235M / 86). When ingesting the original paper, use its self-reported numbers and add a discrepancy note; update concept/synthesis pages that treated the later citation as ground truth (see `edge-cases.md` "Citation Discrepancies").

3. **Graphical results are not tables** — Do not transcribe numbers from bar charts or curves. Use qualitative labeled bullet points matching the paper's own discussion (see `edge-cases.md` "Graphical-Only Results").

4. **Entity updates are append-only** — When an author already has a page, append the new paper to `## Key Contributions` with a wikilink; do not rewrite existing bullets or change `created:` (see `page-templates.md` "Updating an existing entity page").

5. **Pick the PDF attachment, not HTML** — Zotero items from IEEE/ACM often have both. HTML attachments are cluttered with publisher chrome; always extract from `application/pdf`.

6. **MinerU figure filenames are deterministic hashes** — Do not guess filenames. Always `LS` the `figures/` directory after extraction to discover actual names before writing embed wikilinks.

7. **`update_indexes.py stats` is mandatory after `add`** — The `add` subcommand inserts rows but does not recompute the `## Statistics` section. Always run `stats` after all `add` calls (or use `batch --stats` which does both in one call), or `wiki/index.md` will show stale totals.

8. **Build hook INFO messages are not errors** — `mkdocs build --strict` may emit `INFO - Doc file 'log.md' contains an unrecognized relative link` for pre-existing issues in `log.md`. These do not fail the build (exit 0) and are not caused by your ingest; do not block on them.

9. **Synthesis pages are optional but high-value** — Not every paper warrants a synthesis update, but when a new paper is a key data point on an existing efficiency/architecture frontier (e.g., a new point on the AEC complexity-vs-quality Pareto curve), add it to the synthesis's sources table and write 1–2 sentences on what it contributes to the cross-source analysis. See SKILL.md Step 9's trigger checklist for the explicit criteria.

10. **Review papers' classifications can be loose** — A review may group cited methods under labels that don't quite fit (e.g., Mienye 2024 lists PercepNet — which is GRU-based — under "Echo State Network applications"). When ingesting a review, flag any such loose classifications in both the source page and the affected concept page. Do *not* propagate the loose classification as if it were the original paper's own claim. See `edge-cases.md` "Loose Classifications in Review Papers".

11. **Concept-page threshold prevents index bloat** — Resist creating pages for every term a paper mentions. Generic ML/DL primitives (Adam, ReLU, gradient clipping, dropout) do not warrant pages unless the paper makes a *contribution* to them. The Mienye 2024 ingest initially created pages for `adam-optimizer`, `activation-functions`, `gradient-clipping`, `neural-architecture-search` — these are borderline and should be promoted to wikilinks only when a future paper contributes a distinctive formulation of them. See `page-templates.md` "Concept-Page Threshold" for the explicit criteria.

12. **Batch the index updates** — For an ingest creating >3 pages, write a YAML manifest and use `update_indexes.py batch --manifest ... --stats` instead of chaining 10+ `add` calls. The Mienye 2024 ingest required 17 separate `add` calls; the batch subcommand collapses this to one.

13. **Parallel Edits to the same file silently race** — When updating an existing page with multiple changes (frontmatter date, new body section, Related Concepts/Sources extension), the changes must be applied as **sequential Edit tool calls, one per assistant message**, not as parallel calls in a single message. Parallel Edits to the same file race against each other: one edit's `old_string` match is computed against the original file content, but by the time it is applied, another edit has already mutated the file, so only one edit persists and the others are silently dropped. The Apostolidis 2026 ingest hit this — multiple concept pages (mpdr-beamformer, mvdr-beamformer, multi-channel-speech-enhancement, beamforming, relative-transfer-function, jesper-jensen, zheng-hua-tan) lost sections and required a follow-up "complete pending edits" commit. **Always re-Read the relevant section after a multi-edit batch to verify each edit landed.** `commit_ingest.py` now emits `WARN: uncommitted changes remain after commit` when this happens — treat that warning as a signal to inspect. Parallel Edits to **different** files are safe and encouraged.

14. **Windows cp1252 console chokes on non-ASCII author names** — `subprocess.run(..., text=True)` without `encoding='utf-8'` uses the system codepage on Windows (cp1252), which cannot decode characters like "Ø" in "Østergaard" — causing `UnicodeDecodeError` in `commit_ingest.py` when parsing `git status --short` output. All paper-reader scripts that capture subprocess output now pass `encoding='utf-8', errors='replace'` and reconfigure `sys.stdout`/`sys.stderr` to UTF-8. When adding new scripts that call `subprocess.run` with `text=True`, always set `encoding='utf-8', errors='replace'`.

15. **`commit_ingest.py` previously did not stage `wiki/synthesis/index.md`** — Synthesis index updates would silently land outside the commit, then get folded into the next unrelated ingest. The script now stages `wiki/synthesis/index.md` (skipping gracefully if it does not exist).

16. **arXiv-only papers skip `prepare_paper.py` unless HTML extraction fails** — `extract_arxiv_html.py` auto-creates `raw/papers/{slug}/` and exits 2 on HTML 404 or missing `defuddle`, at which point you fetch a PDF via `prepare_paper.py` and continue with MinerU. See SKILL.md Step 3b-3c for the full fallback flow.

17. **`commit_ingest.py` auto-stages unlisted `wiki/` edits** — Step 8 edits to existing concept/entity pages (bidirectional cross-references) are auto-detected and staged; you don't need to pass them via `--concepts`/`--entities`/`--synthesis`. The Chen 2023 ingest initially dropped 4 edited concept pages (`bark-scale-spectral-features`, `deep-filtering`, `erb-scale`, `fixed-rate-skipping`) because they weren't listed; auto-stage prevents this. Pass `--strict` to disable. See SKILL.md Step 13 for the full staging behavior.

18. **All Python scripts must be invoked via `uv run python`** — Never call `python .agents/skills/...` directly. The project's Python environment is managed by `uv` (workspace root has `pyproject.toml` / `uv.lock`); invoking bare `python` may use a different interpreter that lacks required deps (e.g., `pyyaml` for `update_indexes.py batch --manifest`). All SKILL.md usage examples and script docstrings use `uv run python .agents/skills/<skill>/scripts/<script>.py`. The only exception is `build_check.py`'s internal `subprocess.run(['python', '-m', 'mkdocs', ...])` which is a defensive fallback after `uv run mkdocs` fails (do not change). If you copy a command from a pre-2026-07-20 doc that uses bare `python`, prefix it with `uv run`.

19. **`[Text] (Parenthesized)` in entity bullets breaks the build** — MkDocs parses `- Co-authored [Short Title] (Venue Year)` as a markdown link to a nonexistent page. Always quote paper titles: `- Co-authored "Short Title" (Venue Year) — [[sources/{slug}|Author Year]]`. The Härmä 2000 ingest hit this on all 6 entity pages simultaneously. See `page-templates.md` "Updating an existing entity page".

20. **Figure hash filenames must be verified character-by-character** — MinerU produces long SHA-256-style filenames; a single-character typo (`da778` vs `da578`) aborts `mkdocs build --strict`. Always Glob with a partial hash prefix (e.g., `raw/papers/{slug}/figures/3c0491873b*`) and copy the exact result — never type hashes from memory. See `page-templates.md` "Figure Usage" for the verification procedure.

21. **Tutorial/survey papers may warrant many figures** — The old "max 3 figures" rule (removed 2026-07-23) would have discarded essential content from tutorials like Härmä 2000 (27 figures, ~18 useful: phase responses, filter structures, listening-test curves). See `review-papers.md` "Figure Selection" and `page-templates.md` "Figure Usage" for current criteria.

22. **Tutorial papers need per-application subsections** — Don't collapse many application areas (e.g., Härmä 2000 surveys 7: warped FFT, WLP, adaptive filtering, loudspeaker EQ, guitar body modeling, HRTF design, waveguide mesh) into one paragraph; use a summary table + dedicated `###` per application. See `review-papers.md` "Source-Page Required Sections".

23. **MinerU language code is `ch`, NOT `zh`** — `zh` is invalid and fails with `[-10002] field "language" is invalid`. Use `ch` for Chinese (MinerU's default). The Liang Wenfeng 2026 ingest hit this on first attempt with `--language zh`. The full valid-code table is in SKILL.md Step 3c and `extract_mineru.py --help`; the script validates locally before calling the API.

24. **Non-academic PDF sources (transcripts, interviews, presentations) are valid ingests** — Substantive primary-source PDFs that aren't papers benefit from the full workflow (Zotero metadata, MinerU extraction, structured wiki pages). Adapt the source-page template: replace academic sections with themed ones (e.g., Vision & Strategy / Q&A / Key Quotes); slug follows thought-piece convention without a year (e.g., `liang-wenfeng-investor-exchange-meeting`, matching `karpathy-llm-os` and `jensen-huang-nvidia-moat`). The Liang Wenfeng 2026 ingest was the first such case. See SKILL.md "When NOT to Invoke" for the full exception.
25. **Figure files ≠ figure panels — run `map_figures.py` instead of doing forensics by hand** — MinerU extracts papers as many hash-named JPEG crops (the PCEN 2019 ingest produced 14 files for 6 figures) and inlines only *some* into `full-text.md`; multi-panel figures are split per-panel and axis/colorbar strips are extracted but never referenced. Manually mapping hashes to "Fig. N." captions via PDF rendering + template matching wasted ~15 tool calls on that ingest. `scripts/map_figures.py --slug {slug}` pairs each crop with its caption (line proximity in `full-text.md`), prints dimensions, flags unreferenced strips, and exits 2 on referenced-but-missing hashes — one call instead of the manual procedure. Caveat: it assigns by line distance, so a crop *after* a caption still gets that caption; verify ambiguous multi-panel figures against the sub-label lines it prints.

26. **Multi-panel figures must be embedded panel-by-panel** — MinerU splits (a)/(b) figures into separate files. Embed each panel as its own `![[...|(a) ...]]` / `![[...|(b) ...]]` line above the shared `*Figure N: ...*` caption; do not embed a single cropped panel as a stand-in for the whole figure. The PCEN Fig. 1 (soundscape: logmelspec vs PCEN) was 4 crops: two full panels plus two sub-crops; only the two 659×142 panels were actual (a)/(b) content, the 660×248/660×212 crops were decorative sub-regions that `map_figures.py` correctly grouped under the same caption.

27. **Use embed wikilinks for figures, never markdown `![alt](path)`** — Source pages must reference figures as `![[raw/papers/{slug}/figures/HASH.jpg|caption]]`. Markdown image syntax resolves relative to the page, not the vault root, so it breaks in Obsidian and violates the link conventions. The Lostanlen 2019 ingest initially wrote `![...](b2d364...jpg)` (bare filename) and had to rewrite all four figure lines as embed wikilinks.

28. **The Material-for-MkDocs "MkDocs 2.0" banner is cosmetic** — `mkdocs build --strict` may print a multi-line warning from the Material theme about an upcoming MkDocs 2.0 (plugin removal, theme rewrites, "currently unlicensed", etc.) with a link to a blog post. This is a theme-level announcement, not a build error; the build still exits 0 and `build_check.py` reports `BUILD OK: mkdocs build --strict passed (exit 0)`. Do not treat it as a failure or block on it. (Distinct from pitfall #8, which covers `INFO` messages about `log.md` links.)

29. **Triage synthesis pages with `triage_synthesis.py` before reading them** — Reading full synthesis pages to decide whether to update them is expensive (some are 200–400 lines). The Gil-Cacho 2009 ingest read two full synthesis pages (412 + 227 lines, zero tag overlap with the paper) only to decide *not* to update either. Instead, run `uv run python .agents/skills/paper-reader/scripts/triage_synthesis.py --slug SLUG`, which reads the `tags:` from the source page frontmatter (Step 5) and each `wiki/synthesis/*.md` frontmatter via proper YAML parsing, and prints only the pages that share at least one tag. If nothing matches, skip Step 9 entirely. See SKILL.md Step 9 "Triage procedure".
