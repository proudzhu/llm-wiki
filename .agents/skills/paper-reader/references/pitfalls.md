# Common Pitfalls

Concrete lessons from prior ingests. Skim before starting an ingest; consult when something unexpected happens.

1. **Brace glob on Windows fails silently** — `wiki/entities/{a,b,c}.md` returns "No file found" even when files exist. Use `LS` on the directory (filenames are ground truth) or multiple parallel Globs (see SKILL.md "Checking Existing Pages" and pitfall #43).

2. **Citation discrepancies propagate** — Later papers often cite earlier work with wrong numbers (e.g., EchoFree 2025 cited Seidel 2024 with 1.62M params / 107 MMACs/s / 100 Bark bands, but the original reports 1.58M / 235M / 86). Use the original paper's self-reported numbers and add a discrepancy note; update concept/synthesis pages that treated the later citation as ground truth (see `edge-cases.md` "Citation Discrepancies").

3. **Graphical results are not tables** — Do not transcribe numbers from bar charts or curves. Use qualitative labeled bullet points matching the paper's own discussion (see `edge-cases.md` "Graphical-Only Results").

4. **Entity updates are append-only** — Append the new paper to `## Key Contributions` with a wikilink; do not rewrite existing bullets or change `created:` (see `page-templates.md`).

5. **Pick the PDF attachment, not HTML** — Zotero items from IEEE/ACM often have both. HTML attachments are cluttered with publisher chrome; always extract from `application/pdf`.

6. **MinerU figure filenames are deterministic hashes** — Do not guess filenames. Always `LS` the `figures/` directory after extraction to discover actual names before writing embed wikilinks.

7. **`update_indexes.py stats` is mandatory after `add`** — The `add` subcommand inserts rows but does not recompute the `## Statistics` section. Use `batch --stats` (does both in one call), or run `stats` after all `add` calls.

8. **Build hook INFO messages are not errors** — `mkdocs build --strict` may emit `INFO - Doc file 'log.md' contains an unrecognized relative link` for pre-existing issues in `log.md`. These do not fail the build (exit 0).

9. **Synthesis pages are optional but high-value** — Not every paper warrants a synthesis update, but when a new paper is a key data point on an existing efficiency/architecture frontier, add it to the synthesis's sources table and write 1–2 sentences on what it contributes to the cross-source analysis. See SKILL.md Step 9's trigger checklist.

10. **Review papers' classifications can be loose** — A review may group cited methods under labels that don't quite fit (e.g., Mienye 2024 lists PercepNet — which is GRU-based — under "Echo State Network applications"). Flag such loose classifications in both the source page and the affected concept page; do *not* propagate them as if they were the original paper's own claim (see `edge-cases.md`).

11. **Concept-page threshold prevents index bloat** — Resist creating pages for every term a paper mentions. Generic ML/DL primitives (Adam, ReLU, gradient clipping, dropout) do not warrant pages unless the paper makes a *contribution* to them (see `page-templates.md`).

12. **Batch the index updates** — For an ingest creating >3 pages, write a YAML manifest and use `update_indexes.py batch --manifest ... --stats` instead of chaining 10+ `add` calls.

13. **Parallel Edits to the same file silently race** — When updating an existing page with multiple changes (frontmatter date, new body section, Related Concepts/Sources extension), apply them as **sequential Edit tool calls, one per assistant message**, not as parallel calls in a single message. Parallel Edits to *different* files are safe and encouraged. `commit_ingest.py` emits `WARN: uncommitted changes remain after commit` when an edit was silently dropped — treat that warning as a signal to inspect. The Apostolidis 2026 ingest hit this and required a follow-up "complete pending edits" commit. **Recurred twice more** (Xiao 2023, Sun 2024 — the synthesis page in Step 9 and `wiki/index.md` in Step 10, not just Step 8 concept pages) despite this note; SKILL.md now carries a top-level "Same-File Edit Discipline" section. See also #46 for the duplication hazard when re-applying dropped edits.

14. **Windows cp1252 console chokes on non-ASCII author names** — `subprocess.run(..., text=True)` without `encoding='utf-8'` uses the system codepage (cp1252), which cannot decode "Ø" in "Østergaard". All paper-reader scripts pass `encoding='utf-8', errors='replace'` and reconfigure `sys.stdout`/`sys.stderr` to UTF-8. When adding new scripts that call `subprocess.run` with `text=True`, always set `encoding='utf-8', errors='replace'`.

15. **`commit_ingest.py` previously did not stage `wiki/synthesis/index.md`** — Synthesis index updates would silently land outside the commit. The script now stages `wiki/synthesis/index.md` (skipping gracefully if it does not exist).

16. **arXiv-only papers skip `prepare_paper.py` unless HTML extraction fails** — `extract_arxiv_html.py` auto-creates `raw/papers/{slug}/` and exits 2 on HTML 404 or missing `defuddle`, at which point you fetch a PDF via `prepare_paper.py` and continue with MinerU.

17. **`commit_ingest.py` auto-stages unlisted `wiki/` edits** — Step 8 edits to existing concept/entity pages (bidirectional cross-references) are auto-detected and staged; you don't need to pass them via `--concepts`/`--entities`/`--synthesis`. Pass `--strict` to disable.

18. **All Python scripts must be invoked via `uv run python`** — Never call `python .agents/skills/...` directly. The project's Python environment is managed by `uv`; invoking bare `python` may use a different interpreter that lacks required deps (e.g., `pyyaml` for `update_indexes.py batch --manifest`).

19. **`[Text] (Parenthesized)` in entity bullets breaks the build** — MkDocs parses `- Co-authored [Short Title] (Venue Year)` as a markdown link to a nonexistent page. Always quote paper titles: `- Co-authored "Short Title" (Venue Year) — [[sources/{slug}|Author Year]]` (see `page-templates.md`).

20. **Figure hash filenames must be verified character-by-character** — MinerU produces long SHA-256-style filenames; a single-character typo (`da778` vs `da578`) aborts `mkdocs build --strict`. Always Glob with a partial hash prefix (e.g., `raw/papers/{slug}/figures/3c0491873b*`) and copy the exact result — never type hashes from memory.

21. **Tutorial/survey papers may warrant many figures** — Do not cap figure count artificially. Tutorial papers like Härmä 2000 had 27 figures (~18 useful: phase responses, filter structures, listening-test curves). See `review-papers.md` "Figure Selection".

22. **Tutorial papers need per-application subsections** — Don't collapse many application areas into one paragraph; use a summary table + dedicated `###` per application (see `review-papers.md`).

23. **MinerU language code is `ch`, NOT `zh`** — `zh` is invalid and fails with `[-10002] field "language" is invalid`. Use `ch` for Chinese (MinerU's default). The script validates locally before calling the API.

24. **Non-academic PDF sources (transcripts, interviews, presentations) are valid ingests** — Adapt the source-page template: replace academic sections with themed ones (e.g., Vision & Strategy / Q&A / Key Quotes); slug follows thought-piece convention without a year (e.g., `liang-wenfeng-investor-exchange-meeting`).

25. **Figure files ≠ figure panels — run `map_figures.py` instead of doing forensics by hand** — MinerU extracts papers as many hash-named JPEG crops and inlines only *some* into `full-text.md`; multi-panel figures are split per-panel and axis/colorbar strips are extracted but never referenced. `scripts/map_figures.py --slug {slug}` pairs each crop with its caption (line proximity), prints dimensions, flags unreferenced strips, and exits 2 on referenced-but-missing hashes — one call instead of the manual procedure. Caveat: it assigns by line distance, so a crop *after* a caption still gets that caption; verify ambiguous multi-panel figures against the sub-label lines it prints.

26. **Multi-panel figures must be embedded panel-by-panel** — MinerU splits (a)/(b) figures into separate files. Embed each panel as its own `![[...|(a) ...]]` / `![[...|(b) ...]]` line above the shared `*Figure N: ...*` caption; do not embed a single cropped panel as a stand-in for the whole figure.

27. **Use embed wikilinks for figures, never markdown `![alt](path)`** — Source pages must reference figures as `![[raw/papers/{slug}/figures/HASH.jpg|caption]]`. Markdown image syntax resolves relative to the page, not the vault root, so it breaks in Obsidian.

28. **The Material-for-MkDocs "MkDocs 2.0" banner is cosmetic** — `mkdocs build --strict` may print a multi-line warning from the Material theme about an upcoming MkDocs 2.0 (plugin removal, theme rewrites, "currently unlicensed"). This is a theme-level announcement, not a build error; the build still exits 0. (Distinct from pitfall #8.)

29. **Triage synthesis pages with `triage_synthesis.py` before reading them** — Reading full synthesis pages to decide whether to update them is expensive (some are 200–400 lines). Run `triage_synthesis.py --slug SLUG`, which prints only the synthesis pages that share at least one tag with the source page. If nothing matches, skip Step 9 entirely.

30. **Triage thin-match heuristic: skip candidates with only a broad-topic tag overlap** — When the triage output shows `Shared tags (1): <broad-topic>` (e.g. `speech-enhancement`, `beamforming`, `audio-processing`, `signal-processing`, `machine-learning`), the match is almost certainly topical coincidence — skip without reading. Read the candidate only if N ≥ 2, or N = 1 with a contribution-specific tag (e.g. `lpcnet`, `packet-loss-concealment`). The Tashev 2008 ingest had 5 triage candidates sharing only `speech-enhancement`; all correctly skipped without reading.

31. **RunCommand PowerShell `$_` and `$env:` get stripped by the shell wrapper** — Invoking PowerShell cmdlets that use automatic variables (`$_`, `$args`, `$PID`) via RunCommand causes "item not recognized" errors because the shell wrapper mangles `$`-prefixed tokens. **Workaround**: use the Grep tool with alternation (`pattern: "wiener|gcc"`, `path: wiki/concepts`, `output_mode: files_with_matches`) to batch-check page existence — it calls ripgrep directly and avoids PowerShell quoting entirely.

32. **`map_figures.py` may report "no 'Fig. N.' captions found"** — The caption regex (`CAP_RE`) requires punctuation after the number (`Fig. 1.`, `Fig. 2:`, `Figure 3)`), so it skips in-text references like "Figure 1 compares..." (correct) but also misses non-standard caption formats where the label and number are on a separate line from the caption text, or where the caption uses unexpected punctuation (e.g., Jin et al. 2017 uses "Fig. 1 (a)" with a sub-label immediately after the number). **The script now automates this fallback**: when no caption lines exist it anchors on the first in-text "Fig. N" reference of each figure number and pairs crops by line proximity (mode `in-text` in the JSON output; a stderr NOTE flags it). The pairing is heuristic — verify multi-panel figures against the sub-labels the script prints. The manual procedure (read text for "Fig. N" mentions, match nearest image by line) remains only for papers with *neither* caption lines *nor* in-text references, or for resolving ambiguous pairings.

33. **Do not embed unreferenced figure files** — MinerU often splits off axis strips, colorbars, and sub-panel crops that `full-text.md` never references. `map_figures.py` lists these under "Unreferenced files in figures/" with dimensions and a `<-- likely axis/colorbar strip, skip` flag for wide-and-short crops (height < 20% of width). Embedding these in the source page adds visual clutter and wastes reader attention. Only embed figures that are (i) referenced in `full-text.md` AND (ii) paired with a caption by `map_figures.py` or manually matched to a "Fig. N" reference. The Jin 2017 ingest had 13 unreferenced files (11 strips + 2 small crops); none were embedded.

34. **Batch existence checks with Grep alternation, not N Glob calls** — When checking whether 5–15 candidate concept slugs already exist, do NOT issue one Glob per slug (5–15 tool calls). Instead, use a single Grep with alternation: `pattern: "slug-1|slug-2|slug-3"`, `path: wiki/concepts`, `output_mode: files_with_matches`. This returns all matching files in one call. The Jin 2017 ingest initially used 9 parallel Glob calls for individual concept slugs — wasteful and avoidable. This applies to both Step 7 (check before creating) and Step 8 (identify existing pages to update).

35. **Verify index entries landed — statistics alone are not proof** — The Guldenschuh 2014 ingest updated the `## Statistics` section correctly (1182/519/454/180 all matched actual file counts) but the new table rows in `wiki/index.md` and the subdirectory indexes were missing — statistics and table rows are edited independently, and context compression between the two edits can silently drop the rows. After Step 10, always Grep the wiki tree for each new slug (`pattern: "slug-1|slug-2"`, `path: wiki`, `output_mode: content`) and confirm each slug appears in **both** `wiki/index.md` and `wiki/{category}/index.md`.

36. **`triage_synthesis.py` requires the source page to exist first** — The script reads the source page's frontmatter tags to find synthesis candidates; running it before Step 5 (source-page creation) fails with `ERROR: source page not found`. The workflow step order (5 → 9) already encodes this dependency, but during execution the temptation to "run the cheap triage early" causes exactly this failure — seen in the Guldenschuh 2014 ingest. Triage is cheap but not order-free.

37. **Never run raw git commit commands via RunCommand on PowerShell 5.1** — The shell is PowerShell 5.1, which does NOT support `&&` as a statement separator or bash heredocs (`<<'EOF'`); both produce parser errors ("标记"&&"不是此版本中的有效语句分隔符"). Always use `commit_ingest.py` (Step 13), which stages and commits correctly. If raw git is genuinely needed: chain with `;`, quote commit messages with single quotes, and put each git command in a separate RunCommand call. Also note: `.obsidian/` config churn and line-ending-only diffs (a file shows `M` in `git status` but empty `git diff`) should be excluded from ingest commits — `commit_ingest.py` handles this scoping automatically.

38. **Mermaid diagrams silently render as code blocks without superfences `custom_fences`** — A ```mermaid block in a source page passes `mkdocs build --strict` (exit 0) even when `mkdocs.yml` lacks the `pymdownx.superfences.custom_fences` mermaid entry — the build emits `<div class="highlight"><pre><code>flowchart TB...` and the browser shows plain syntax-highlighted text instead of a diagram. Obsidian renders mermaid natively, so the failure is MkDocs-only and invisible to the build. The config is now in place in this repo (added 2026-08-30); when adding mermaid to a page, verify the built HTML contains `<pre class="mermaid">` (Grep `site/sources/{slug}.html` for `class="mermaid"`). Full syntax rules for both renderers: `page-templates.md` "Neural-Network Model Documentation".

39. **NN papers must document architecture, I/O, and losses — not just cite the paper's figure** — Source pages for neural-network papers require a `### Model Structure, Inputs, and Outputs` section (mermaid data-flow diagram + per-network spec tables with structure/inputs/outputs/training-data/role) and a `### Training Losses` section (total objective + per-term equations with coefficient values, noting which network each loss trains). Citing "see Fig. 2 of the paper" alone is insufficient — the wiki page must be self-contained. See `page-templates.md` "Neural-Network Model Documentation" for the template and the worked example (`valin-2022-real-time-plc.md`).

40. **Log-entry markdown links with `../` targets abort the strict build** — A log body written with `[Title](../sources/foo.md)` produces `WARNING - Doc file 'log.md' contains a link '../sources/foo.md', but the target is not found` and fails `mkdocs build --strict` at commit time (the Ke 2021 ingest appended 12 such links; the commit hook caught them because `build_check.py` had been masking warnings — see pitfall #41). From `wiki/log.md`, `../` escapes the MkDocs docs root. Reference pages in log bodies with **vault-absolute wikilinks** (`[[sources/foo|Title]]`) or **backticked plain paths** (`wiki/sources/foo.md`), matching the style of earlier entries. `append_log.py` now rejects bodies containing `](../...` or `](wiki/...` links (exit 2) before appending.

41. **`--quiet` masks mkdocs strict-mode warnings — `build_check.py` must run verbose** — mkdocs's `--quiet` sets the log level to ERROR, which filters WARNING records before strict-mode's warning counter sees them: a `mkdocs build --strict --quiet` can exit 0 despite strict violations. The Ke 2021 ingest shipped 12 broken log-link warnings: `build_check.py` (then using `--quiet`) reported "BUILD OK" and only the commit-time build failed. `build_check.py` now runs without `--quiet` — INFO-level nav lines in its output are normal and harmless (distinct from #8, which is about INFO not *failing* the build). Never re-add `--quiet` to any strict build used as a gate.

42. **MinerU silently drops minus signs on negative numbers** — The Ke 2021 `full-text.md` rendered the SNR range −5…10 dB as "5 dB to 10 dB" and the test SNRs {−5, 0, 5, 10} as "5, 0, 5, 10" — the minus signs (U+2212 or hyphen-minus adjacent to digits) vanished during extraction. Suspicious patterns: a 1 dB-step SNR sweep that appears to start positive, or a value list with a repeated entry after a sign flip (5, 0, 5, 10 has "5" twice). Cross-check numeric signs against the publisher page, abstract, or PDF before writing them into the source page; for Ke 2021 the springeropen article page confirmed SNR ∈ {−5, 0, 5, 10} dB.

43. **Grep matches file contents, not filenames — never use it as an existence check** — During the Hu 2026 ingest, grepping `wiki/entities` for `romain-serizel` returned only `index.md` even though `entities/romain-serizel.md` exists: entity/concept pages rarely contain their own slug (the H1 is the display name), so a content Grep produces false "missing"; conversely `index.md` contains *every* slug and any page *mentioning* a slug in a wikilink matches, producing false "exists". For existence checks, `LS` the directory and scan filenames — one call covers any number of candidates. Reserve Grep for content searches (does any page mention X?). SKILL.md Steps 6–8 previously recommended the Grep approach; corrected 2026-09-06.

44. **LaTeX math in wikilink aliases aborts the strict build — and passes the old verify_wikilinks check** — Writing `[[concepts/spectrally-adaptive-loss|$\mathcal{L}_{\mathrm{Sig}}$]]` (an alias that is a math expression, tempting when linking loss-function concept pages) mangles the `fix_obsidian_escapes` pipe-escaping: mkdocs reports a link target like `../concepts/spectrally-adaptive-loss|\(/mathcal{L}_{/mathrm{Sig}}\).md` and `mkdocs build --strict` fails. The old `verify_wikilinks.py` (Step 12a) passed — the *slug* resolves fine; only the alias is broken — so the failure surfaced at Step 12b, costing a full 45s build-fail-fix cycle (Zhao & Madhu 2026 ingest). `verify_wikilinks.py` now flags any `$` in a wikilink/embed alias (including `\|`-escaped table-cell variants) before the build. Fix: plain-text alias — `[[concepts/spectrally-adaptive-loss|Spectrally Adaptive Loss]]` or `[[concepts/spectrally-adaptive-loss|the adaptive loss]]` — keeping the LaTeX outside the wikilink.

45. **Zotero searches with full paper titles time out** — Searching `zotero_fetch.py search` with the complete title of a paper ("A LIGHTWEIGHT HYBRID MULTI-CHANNEL SPEECH EXTRACTION SYSTEM WITH DIRECTIONAL VOICE ACTIVITY DETECTION") timed out in the Sun 2024 ingest; a 3–5-word distinctive substring ("directional voice activity detection") found the paper instantly. Long search strings make the Zotero local-API full-text search expensive. Always search with a short, distinctive phrase (ideally rare words from the title), then confirm the match on the returned metadata.

46. **Re-applying dropped parallel edits can DUPLICATE content — always re-read the region first** — After a same-file parallel-edit race (#13), which edits survived is nondeterministic. When re-applying a "lost" edit, an `old_string` that is a *prefix* of the current text (e.g. ending at `...deployment robustness.` when the file already contains `...deployment robustness. Sun 2024 adds...`) still matches, and the Edit inserts the addition *before* the surviving copy — producing the sentence twice. This happened in the Sun 2024 ingest: the synthesis Takeaway 1 ended up with the new sentence duplicated after re-application. Rule: after any suspected race, **Read the target region before re-applying**, and construct `old_string` to include enough trailing context that it cannot match text that already contains the addition.

47. **poppler (`pdftotext`) is not installed on this Windows machine — use the pypdf fallback** — Both the Xiao 2023 and Sun 2024 ingests hit MinerU failures (`parsing failed` on both `vlm` and `pipeline` models) *and* found no `pdftotext` binary on PATH, forcing ad-hoc `pymupdf`/`pypdf` extraction scripts written from scratch mid-ingest. `extract_pdftotext.py` (Step 3d) now falls back to `pypdf` automatically when poppler is missing, and `pypdf` is a project dependency (`uv add pypdf`, 2026-09-08). The fallback chain is now: arXiv HTML → MinerU → pdftotext → pypdf, with no environment prerequisite beyond the project venv.

48. **Custom ad-hoc extraction scripts bypass the delete-PDF invariant — manual `git add` then commits `paper.pdf`** — Every standard extraction script deletes `raw/papers/{slug}/paper.pdf` after writing the text, and `commit_ingest.py` refuses to stage `paper.pdf`. An ad-hoc extraction script (see #47) written mid-ingest does neither: the Sun 2024 ingest committed `paper.pdf` because manual `git add raw/papers/{slug}/` staged everything in the directory. If custom extraction is ever needed again: delete the PDF immediately after extraction, or rely on `commit_ingest.py` (Step 13) instead of raw git. (Pre-existing tracked PDFs — fujii-2006, lu-2021, zhan-2025, sun-2024 — remain in history as an accepted inconsistency.)

49. **Zotero creator lists can omit the first author, and `date`/venue are often blank — verify against the PDF before naming anything** — The EUSIPCO 2026 ingest (Zotero `LVZPGG2Q`) returned only **3 of the paper's 4 authors**: the first author, Yile (Angela) Zhang, was missing entirely, and both `date` and `conferenceName` were empty. Because the slug's author segment, the H1, and the Step 6 entity set all derive from the author list, the ingest created `raw/papers/abhayapala-2026-…` and had to rename the whole directory plus every reference mid-run. Rules: (a) treat `zotero_fetch.py metadata`'s creator list as a *lead* — confirm the author list **and order** from the paper itself (`full-text.md` exists by Step 4); (b) the slug's author segment is the **first author as printed on the title page**, not the first creator Zotero happens to list; (c) if `date`/venue is blank, resolve it externally (conference accepted-papers page, publisher page, arXiv) before choosing the year — never default to "today"; (d) note the discrepancy on the source page so the next reader knows the wiki page is deliberate and Zotero is wrong; (e) fix `raw/papers/{slug}/` *before* writing any wiki page, since renaming afterwards means editing every cross-reference. Also ignore `note`-type attachments that sit alongside the PDF (e.g. `[A9WTKYEN] (no title) (note)`).

50. **The `write` tool fails with `EEXIST … mkdir '<dir>'` for files inside pre-existing directories — write to the project root and `mv`** — The EUSIPCO 2026 ingest could not create `wiki/sources/{slug}.md`: four attempts returned `EEXIST: file already exists, mkdir 'D:\Projects\llm-wiki\wiki\sources'` for a directory that plainly exists. Probing (2026-09-11) showed the failure is **path-dependent, not content-dependent** — writes into pre-existing directories failed for `wiki/`, `wiki/sources/`, `wiki/concepts/`, `wiki/queries/`, `raw/`, `schema/`, `scripts/`, `plugins/`, `.obsidian/`, `.githooks/` and `site/`, while writes to the **project root**, to **`.agents/**`**, and to **newly created** directories (e.g. `wiki/zz_newsub/`) succeeded. The tool appears to `mkdir` the parent and re-raise `EEXIST` instead of accepting an existing directory, so **retrying the same path never helps**. Workarounds, in order of preference: (a) **write to the project root, then `mv`** — `write` to `zz_page.tmp.md`, then `mv zz_page.tmp.md wiki/sources/{slug}.md`; this was used for every new page in that ingest, and because `mv` overwrites it also covers the Step 5 re-ingest "overwrite the existing source page" case; (b) **shell heredoc with a *quoted* delimiter** (preserves `$`, backticks and `[[…|…]]` byte-exactly — verified): `cat > wiki/concepts/foo.md <<'ZEOF' … ZEOF`; (c) `edit` is **unaffected** — it modifies existing `wiki/` files normally, so Steps 6/8/9 need no workaround. Delete root-level temp files before committing: `commit_ingest.py` stages only `wiki/` and `raw/`, so a stray temp file stays silently untracked.

51. **A single Edit call with several `edits[]` entries is atomic — one stale anchor aborts the whole file, and nothing is applied** — During the Zhang 2026 ingest, a call with 4 edits for `spatial-covariance-matrix.md` failed on `edits[3]` with "Could not find edits[3]"; the cause was a case mismatch in the anchor (`Real-Time RCSCME-Based` vs the file's `Real-Time RCSCME-based`). **No** edits were applied — a Grep confirmed the file was untouched — so the retry was safe. This atomicity is a feature: it makes the *recommended* pattern safe and fast — **one Edit call per file, carrying that file's frontmatter + body + Related Concepts + Related Sources edits together**, issued in parallel across *different* files. That is one write per file and cannot race; what races is issuing several parallel Edit **calls** against the *same* file (see #13). When a multi-edit call fails, do not assume partial application: Grep for one of the intended additions, re-read the region, and fix the anchor before retrying.

52. **`ls <category-dir> | wc -l` overcounts by one — each category directory contains its own `index.md`** — `ls wiki/sources | wc -l` returned 203 while `check_statistics.py` reported 203 total sources including the new page — i.e. 202 real pages + `index.md`. Never use a directory listing as a page count (and never sanity-check the Statistics block against one). Use `uv run python .agents/skills/wiki-lint/scripts/check_statistics.py`, or the `stats` output from `update_indexes.py`.

53. **`## Related Synthesis` links must be earned by triage, not by conceptual adjacency** — The Zhang 2026 ingest initially listed `secondary-path-modeling-evolution` under Related Synthesis on the reasoning that both concern "path identification". But that synthesis covers the **secondary** path $S(z)$, while the paper identifies the **feedback** path $F(z)$ — and `triage_synthesis.py` had already returned **zero tag overlap** for it, which was the correct signal that there is no cross-source relation to write about. Rule: list a synthesis page under `## Related Synthesis` only if triage surfaced it (tag overlap) *and* you either updated it or can justify why not; check the target synthesis is actually about the paper's subject before claiming it "extends" or "refines" anything.

54. **PowerShell `mv` does NOT overwrite — use `Move-Item -Force`** — `mv` is a PowerShell **alias for `Move-Item`**, which refuses to clobber an existing destination with `Move-Item: 当文件已存在时，无法创建该文件。` ("Cannot create a file when that file already exists"). The Gerkmann 2012 ingest lost all four Step 8 page updates this way — every `mv zz_x.tmp.md wiki/concepts/{page}.md` failed while the earlier create-only `mv` (destination absent) had succeeded, which made the failure look intermittent. Rule: **any** root-temp-file move onto an existing target must be `Move-Item -Force`. This is the only reason the "write to root then move" pattern works for *re-ingestion* (Step 5 overwrite) and for the multi-region-update path in Step 8 — the older note that "`mv` overwrites" was wrong.

55. **`uv run` dies instantly on a cache permission error — export `UV_CACHE_DIR` into the workspace** — Every `uv run python .agents/skills/…` fails with:

    ```
    error: Failed to initialize cache at `D:\Scoop\persist\uv\cache`
      Caused by: failed to open file `…\sdists-v9\.git`: 拒绝访问。 (os error 5)
    ```

    `uv`'s default cache sits outside the workspace, which the file sandbox denies. The error text looks like a corrupt environment or a missing dependency but is purely the cache location. Fix, on **every** call (each shell call is a fresh process, so an exported variable does not persist): `$env:UV_CACHE_DIR = "D:\Projects\llm-wiki\.uv-cache"; uv run python …`. Hit at the very first script call of the Gerkmann 2012 ingest and would otherwise have recurred ~15 times.

56. **Glob caps at 100 paths — it is NOT an existence check for a large category directory** — `Glob wiki/concepts/*.md` returned `(Showing 100 of 502 paths)` in modification-time order. A candidate slug can exist and simply not appear in that window, producing a false "missing" and a duplicate page. The doc's older advice to "LS the directory and scan the filenames" is also unusable: **this harness has no LS/directory-listing tool**. Correct methods, in order: (a) **one Grep with alternation against `wiki/{category}/index.md`**, which holds a row per page (5 candidates resolved in 2 calls in the Gerkmann 2012 ingest); (b) an exact-path Glob for a single candidate (`wiki/concepts/foo.md`) — precise, never capped.

57. **Zotero's `abstract` can be truncated mid-sentence, and page ranges are usually absent** — The Gerkmann 2012 item returned `Abstract: Recently, it has been shown that MMSE-based noise power estimation [1] results in an improved noise tracking performance… The MMSE-based approach em…` — the field is cut off, and `zotero_fetch.py metadata` printed it truncated without any ellipsis warning. It also carried no page range, while the Step 11 log template asks for `pp. XXX–XXX`. Rules: take the abstract from `full-text.md` (available by Step 4), never paraphrase from the truncated Zotero field; **omit** page numbers you could not verify rather than inventing them (a web search for the range cost two calls and returned nothing usable); and note both facts on the source page so the next reader knows the omission was deliberate.

58. **The pre-commit hook cannot run under the file sandbox — `--no-verify` after Step 12b passed** — `commit_ingest.py` stages correctly, then the commit dies with:

    ```
    Commit failed:
      0 [main] sh (12736) …\usr\bin\sh.exe: *** fatal error - couldn't create signal pipe, Win32 error 5
    ```

    MSYS `sh.exe` (which the hook runs) needs a named pipe, and the sandbox forbids that, so the failure is independent of the staged content — retrying, re-staging, or narrowing the file list will not help. Because Step 12b already runs the same `mkdocs build --strict` the hook would run, re-running with `--no-verify` loses no verification. Do this only after a clean Step 12b. Afterwards `WARN: uncommitted changes remain after commit` listing **only** `.obsidian/*.json` is the expected steady state (Obsidian config churn is deliberately excluded, #37); it indicates a dropped edit only when `wiki/` paths appear in that list.

59. **The `edit` tool takes ONE `old_string`/`new_string` pair — there is no `edits[]` array** — SKILL.md Step 8 previously instructed "one Edit call per file, carrying all of that file's changes in its `edits[]` array", and #51 described such a call as atomic. **That tool shape does not exist in this harness.** Following the instruction literally is impossible, and the obvious substitute — several `edit` calls against one file in a single message — is exactly the race that #13 and "Same-File Edit Discipline" warn about. The working pattern for a file needing frontmatter + body + Related Concepts/Sources changes is a **whole-file rewrite**: `write` the complete updated content to the project root, then `Move-Item -Force` it over the target (#54). That is one write per file, so a parallel batch across files cannot race — the Gerkmann 2012 ingest updated four existing pages in a single batch with zero lost writes. A rewrite is safe only when a single Read returned the *entire* file; if the Read carried a `(Showing lines X–Y of N)` trailer, fall back to sequential single `edit` calls, one per message.
